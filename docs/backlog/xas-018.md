# [XAS-018] Add `naps2-scan` skill (scan → OCR → merge → filename proposal)

**Status**: Open
**Priority**: High
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/naps2-scan/

**Summary**:
As a user digitizing paperwork, I want a guided pipeline that drives NAPS2 to scan + OCR a document, merges halves when the input is simplex, and proposes a content-derived filename so that each scan lands as a single, well-named, searchable PDF with minimal manual steps.

**Description**:
New skill wrapping [NAPS2](https://www.naps2.com/) for end-to-end scanning. The skill guides (or executes) the following pipeline:

1. Invoke `NAPS2.Console.exe` with a configured profile to scan into a working directory.
2. Apply OCR (Tesseract via NAPS2) producing a searchable PDF.
3. If the input was simplex (two separate scans — odd pages + even pages), chain into the `simplex-merge` skill to produce a single correctly ordered PDF.
4. Read the OCR text and propose a filename derived from the content (e.g., sender + document type + date).
5. Present the proposal to the user for confirmation before renaming.

Auto-filing (moving the file into a structured folder) is out of scope here — that's `auto-file` (XAS-019).

**Dependencies**:
- NAPS2 installed on Windows (`NAPS2.Console.exe` on `PATH` or a known location)
- Tesseract OCR data installed via NAPS2 for the relevant language(s)
- `simplex-merge` skill (XAS-017) for the merge step

**Open questions**:
- NAPS2 profile name(s) — one default, or selectable per document type?
- Filename proposal heuristics — LLM-classify the OCR text, or rule-based extraction (date regex, first-line heuristic)?
- Working directory — fixed location or per-session temp?

**Acceptance Criteria**:
- [ ] `SKILL.md` created with clear trigger phrases ("scan this", "start scanning", etc.)
- [ ] Documents the expected NAPS2 setup (profile, OCR language)
- [ ] Invokes `NAPS2.Console.exe` correctly (args verified)
- [ ] Chains into `simplex-merge` when two files are produced from a single scan session
- [ ] Proposes a content-based filename from the OCR text
- [ ] Asks for user confirmation before committing the filename
- [ ] Manual end-to-end test: scan a real document and verify output
