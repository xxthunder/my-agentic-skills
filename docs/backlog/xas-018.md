# [XAS-018] Add `naps2-scan` skill (scan → OCR → merge → filename proposal)

**Status**: Done
**Priority**: High
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/naps2-scan/

**Summary**:
As a user digitizing paperwork, I want a guided pipeline that drives NAPS2 to scan + OCR a document, merges halves when the input is simplex, and proposes a content-derived filename so that each scan lands as a single, well-named, searchable PDF with minimal manual steps.

**Description**:
New skill wrapping [NAPS2](https://www.naps2.com/) for end-to-end scanning. The skill guides (or executes) the following pipeline:

1. Invoke `NAPS2.Console.exe` with a configured profile to scan into a working directory.
2. Apply OCR (Tesseract via NAPS2) producing a searchable PDF.
3. If the input was simplex (two separate scans — odd pages + even pages), chain into the `simplex-merge` skill to produce a single correctly ordered PDF.
4. Read the OCR text and propose a filename derived from the content (e.g., sender + document type + date).
5. Present the proposal to the user for confirmation before renaming.

Auto-filing (moving the file into a structured folder) is out of scope here — that's `auto-file` (XAS-015a).

**Dependencies**:
- NAPS2 installed on Windows (`NAPS2.Console.exe` on `PATH` or a known location)
- Tesseract OCR data installed via NAPS2 for the relevant language(s)
- `simplex-merge` skill (XAS-017) for the merge step

**Open questions**:
- NAPS2 profile name(s) — one default, or selectable per document type?
- Filename proposal heuristics — LLM-classify the OCR text, or rule-based extraction (date regex, first-line heuristic)?
- Working directory — fixed location or per-session temp?

**Acceptance Criteria**:
- [x] `SKILL.md` created with clear trigger phrases ("scan this", "start scanning", etc.)
- [x] Documents the expected NAPS2 setup (profile, OCR language)
- [x] Invokes `NAPS2.Console.exe` correctly (args verified)
- [x] Chains into `simplex-merge` when two files are produced from a single scan session
- [x] Proposes a content-based filename from the OCR text
- [x] Asks for user confirmation before committing the filename
- [x] Manual end-to-end test: scan a real document and verify output (see UAT below)

**User Acceptance Test**:

Prerequisites (one-time setup):
- NAPS2 installed; `NAPS2.Console.exe` reachable (via PATH or known path).
- At least one scanner profile configured in the NAPS2 GUI.
- OCR language packs installed via NAPS2 GUI (`Tools → OCR`) — at minimum `eng` and `deu`.
- `xxthunder-paperless-skills` plugin installed locally from the marketplace.

Install the plugin (in Claude Code). Pick one of:

**Local dev install** (use while on a feature branch — reads the working tree directly):

```
/plugin marketplace add <absolute-path-to-repo>
/plugin install xxthunder-paperless-skills@xxthunder-agentic-skills
```

The marketplace name registered is `xxthunder-agentic-skills` (from `.claude-plugin/marketplace.json`), not the directory name. Switching branches or editing files is picked up by `/plugin update` (or remove + reinstall).

**Published install** (once merged to `develop` and pushed):

```
/plugin marketplace add xxthunder/xxthunder-agentic-skills
/plugin install xxthunder-paperless-skills@xxthunder-agentic-skills
```

If switching from local to published, first `/plugin marketplace remove xxthunder-agentic-skills` to avoid a name collision.

Verify: `/plugin` lists `xxthunder-paperless-skills` as installed, and the `naps2-scan` and `simplex-merge` skills appear in the available-skills list. Restart the Claude Code session if the skills do not show up immediately.

Test cases:

1. **Single-sided scan with filename proposal**
   - Place a one-page document (e.g., a letter or invoice) in the scanner.
   - In a fresh working directory, say "scan this letter".
   - Expect: skill asks for profile + OCR language, invokes `NAPS2.Console.exe`, produces `scan.pdf` with embedded OCR text, proposes a filename in `YYYY-MM-DD-sender-topic.pdf` format derived from the document content, renames after confirmation.
   - Verify: final PDF opens, text is selectable/searchable, filename matches proposal.

2. **Simplex double-sided scan with merge chain**
   - Place a two-sided multi-page document in the simplex scanner.
   - Say "scan this double-sided document, simplex scanner".
   - Expect: two passes (odd then even) producing `scan-odd.pdf` and `scan-even.pdf`; skill chains into `simplex-merge` to interleave pages; filename proposal runs on merged PDF.
   - Verify: merged PDF has correct page order (front1, back1, front2, back2, …), OCR works, filename matches content.

3. **Post-processing entry point**
   - Pre-place existing `scan.pdf` (already OCR'd) in the working directory.
   - Say "propose a filename for this scan".
   - Expect: skill skips NAPS2 invocation, reads OCR text, proposes filename, renames on confirmation.

4. **Error handling — missing profile**
   - Say "scan this with profile NonexistentProfile".
   - Expect: NAPS2 reports "profile not found"; skill relays error verbatim and stops without retrying.

5. **Error handling — blank OCR text**
   - Scan a blank or image-only document.
   - Expect: skill detects short/empty OCR text and asks user for filename components directly instead of guessing.
