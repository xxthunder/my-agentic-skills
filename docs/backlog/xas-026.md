# [XAS-026] CI / GitHub Actions setup

**Status**: In Progress
**Priority**: High
**Component**: `.github/workflows/`, `pyproject.toml`

**Summary**:
As a maintainer, I want CI on every push and PR to `develop` so that broken changes are caught before merge and contributors get fast, automated feedback.

**Description**:
The repo currently has no CI. With the pytest harness landed (XAS-015c) and a public marketplace, we need foundational automation:

1. Automated test execution on every change with a green/red signal
2. Coverage and structured test-result visibility (Codecov + JUnit report)
3. Plugin/marketplace JSON schema validation to catch malformed manifests before they ship
4. PR-title conventional-commit linter so squash-merges land in `develop` already correctly formatted
5. Interactive `@claude` bot for issue/PR triage and review (dogfoods our own marketplace)

Modeled after the `xxthunder/shortcuts` repo's CI (Pester-based), with `uv run pytest` substituted for Pester. Triggers target `develop` only — the repo has no `main` branch.

**Substories**:
- XAS-026a — Pytest workflow on push/PR (matrix: ubuntu + windows)
- XAS-026b — Coverage upload + JUnit test report
- XAS-026c — Claude Code interactive bot (`@claude` mentions)
- XAS-026d — JSON schema validation for `marketplace.json` and `plugin.json`
- XAS-026e — PR title conventional-commit linter
- XAS-026f — Coverage thresholds via `codecov.yml` (follow-up to XAS-026b)
- XAS-026g — Codecov status badge in README (follow-up to XAS-026b)

**Acceptance Criteria**:
- [ ] CI status check appears on PRs to `develop` within ~5 minutes of push
- [ ] Coverage and JUnit reports visible on PR pages
- [ ] Manifest schema check fails on a deliberately malformed `plugin.json`
- [ ] `@claude opus` and `@claude sonnet` both work in a PR comment from a collaborator
- [ ] PR with a non-conventional title fails the title-lint check
