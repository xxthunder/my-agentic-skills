# [XAS-022] Migrate `simplex-merge` to `uv`-run script with PEP 723 deps

**Status**: Done
**Priority**: Medium
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/simplex-merge/

**Summary**:
As a user of `simplex-merge`, I want the skill to rely on a shipped, versioned merge script instead of an inline Python recipe, so that I don't need to manually `pip install PyPDF2` and the merge logic (including the unequal-page-count edge case) is deterministic rather than re-derived each session.

**Description**:
`simplex-merge` currently instructs Claude to write an inline Python snippet using the deprecated `PyPDF2` package and asks the user to `pip install` it. This has the same drawbacks as the pre-XAS-021 state of `naps2-scan`: fragile inline invocations, Windows-path quoting hazards, a manual Python dependency prerequisite, and the risk that Claude re-derives the interleave logic incorrectly on edge cases.

This story ports the pattern established in XAS-021 to `simplex-merge`: ship a `scripts/merge.py` file with [PEP 723](https://peps.python.org/pep-0723/) inline metadata, declare `pypdf>=4`, and invoke it via `uv run`. Update `SKILL.md` to call the script instead of inlining Python.

**Scope Decisions**:
- **One script, one responsibility**: `merge.py` interleaves odd + reversed-even pages into one PDF. No `--strip-blank-pages` flag — that remains prose-driven in SKILL.md Step 3 since it's rare, user-initiated, and page-index-known.
- **Upgrade `PyPDF2` → `pypdf`** as part of the migration (PyPDF2 is the deprecated upstream name; same swap as XAS-021).
- **`uv` becomes a prerequisite** for this skill too. This is a zero-cost bump for users who already have `naps2-scan` installed from the same plugin (XAS-021 already declared `uv` as a prereq there).
- **Plugin-level minor bump** (`0.4.0 → 0.5.0`) — users who previously used `simplex-merge` alone now need `uv`, which is a behavior-level prerequisite change.

**Dependencies**:
- XAS-017 (simplex-merge skill base)
- XAS-021 (established the uv-run scripts pattern)

**Acceptance Criteria**:
- [x] `scripts/merge.py` ships under the skill with a PEP 723 header declaring `pypdf>=4`
- [x] Script CLI: `merge.py <odd.pdf> <even.pdf> <output.pdf>` — reverses even pages, interleaves, handles unequal page counts
- [x] `SKILL.md` Step 2 invokes the script via `uv run` instead of inlining Python
- [x] `SKILL.md` gains a Prerequisites section naming `uv` (with install instructions consistent with `naps2-scan`)
- [x] `SKILL.md` no longer mentions `PyPDF2` or `pip install`
- [x] Plugin version bumped in `plugin.json` and `marketplace.json` (`0.4.0 → 0.5.0`)
- [x] Manual UAT: run `simplex-merge` on a real pair of simplex scans and verify correct interleaving; also test an unequal-page-count pair
