# [XAS-025] ✅ DONE - Scrum conventions and backlog-ops skill

**Status**: Done (2026-04-21)
**Priority**: High
**Component**: plugins/xxthunder-dev-skills/skills/refinement/, plugins/xxthunder-dev-skills/skills/backlog-ops/, plugins/xxthunder-dev-skills/skills/tdd-workflow/, docs/backlog/

**Summary**:
As a maintainer using these dev skills, I want the backlog to support emergent epics via a letter-suffix ID convention and a dedicated skill for lifecycle state changes so that hierarchy stays implicit, the README TOC stays flat, and status transitions are consistent across item files and the TOC.

**Description**:
The current backlog explicitly labels epics and groups stories under headings in `README.md`, which duplicates information and creates drift. Replace this with:

- An implicit epic model: top-level items are `PREFIX-###`; substories are `PREFIX-###<letter>`. An item is an epic iff at least one letter-suffix sibling exists. No explicit `**Type**: Epic` field; no explicit `**Epic**:` back-reference.
- A flat TOC in `README.md` — natural ID sort groups substories after their epic.
- A status cascade rule for epics: an epic stays out of `Done` while any substory is not `Done`.

Add a new `backlog-ops` skill to the `xxthunder-dev-skills` plugin that handles the mechanical lifecycle operations (pull, check an AC/UAT, complete) with the epic cascade, staging edits only (never commits — those ride with the related code change). Update `tdd-workflow` to reference `backlog-ops` at cycle boundaries (pull at start, complete at end; no mid-cycle auto-checks). Migrate Open / In-Progress items to the letter-suffix convention; leave Done items on their bare IDs.

**Scope Decisions**:
- Keep conventions inside the existing `refinement` skill's `backlog-format.md`; do not create a separate "scrum" skill just for ID conventions.
- `backlog-ops` is a mechanics skill only — no estimation, sprint, or velocity concepts.
- `tdd-workflow` suggests invoking `backlog-ops` but does not auto-check ACs mid-cycle (the user names which AC a cycle satisfied).
- Only rename Open and In-Progress items to the new convention; Done items keep their bare IDs to avoid churning git history.
- `backlog-ops` stages file edits only — it never produces its own commit. Backlog edits ride in the user's next commit alongside the code change.
