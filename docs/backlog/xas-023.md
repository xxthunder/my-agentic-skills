# [XAS-023] Fix skill trigger descriptions so new scans pick `naps2-scan`

**Status**: Done
**Priority**: High
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/{simplex-merge,naps2-scan}/

**Summary**:
During UAT of XAS-021/XAS-022, the prompt "Let's scan another multi pages document" caused Claude Code to load `simplex-merge` and search for existing scan files instead of loading `naps2-scan` to start a new scan. This is a skill-triggering defect: `simplex-merge`'s description is too scan-dense for a post-processing-only skill, and `naps2-scan`'s trigger list doesn't cover conversational rephrasings like "scan another" or "let's scan".

**Description**:
Claude Code picks skills by matching the user's intent against each skill's frontmatter `description`. Two problems produced the wrong selection:

1. `simplex-merge`'s description leads with "Merge two PDF files from a simplex (single-sided) scanner" and peppers "scanned"/"scanning" throughout, even though the skill is strictly post-processing on two already-existing PDFs. This creates false-positive matches on scan-related prompts.
2. `naps2-scan`'s trigger list is verbatim-phrase heavy ("scan this", "start scanning", "digitize this") and misses conversational variants ("scan another", "let's scan", "new scan", "scan again").

Fix both, with a negative anchor in `simplex-merge` pointing at `naps2-scan` for new scans.

**Scope Decisions**:
- Description-only fix in both SKILL.md files; no code/script changes.
- Also sync the body "When to Use" / "When This Skill Triggers" sections to match the frontmatter so documentation and triggers agree.
- Patch-level plugin bump (`0.5.0 → 0.5.1`) — no functional change, just corrected routing.

**Acceptance Criteria**:
- [x] `simplex-merge` frontmatter leads with the merge operation, not scanning
- [x] `simplex-merge` requires "two existing PDF files" as precondition in the description
- [x] `simplex-merge` carries an explicit negative anchor: "do NOT use to start a new scan; use naps2-scan"
- [x] `simplex-merge` body gains a "When to Use / When NOT to Use" section consistent with frontmatter
- [x] `naps2-scan` frontmatter covers "scan another", "scan again", "let's scan", "new scan", "scan the next one"
- [x] `naps2-scan` "When This Skill Triggers" list mirrors the expanded frontmatter
- [x] Plugin version bumped `0.5.0 → 0.5.1` in `plugin.json` and `marketplace.json`
- [x] Manual UAT: "Let's scan another multi pages document" loads `naps2-scan`, not `simplex-merge`; "merge these two files" still loads `simplex-merge`
