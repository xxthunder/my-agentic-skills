# [XAS-031] ✅ DONE - `commit-helper` cites the verification gate instead of restating it

**Status**: Done (2026-08-23)
**Priority**: Low
**Component**: `plugins/xxthunder-dev-skills/skills/commit-helper/SKILL.md`,
`plugins/xxthunder-dev-skills/.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json`

**Related**: Found reviewing all dev skills alongside
[XAS-030](xas-030.md). Same shape as [XAS-027k](xas-027k.md): a document
restating something another artifact owns.

**Summary**:
As a maintainer, I want `commit-helper`'s pre-commit checks to invoke the
stronger discipline that already exists, so that the reliable trigger pulls in
the better-written gate instead of a weaker paraphrase of it.

**Description**:
`commit-helper` opens with a Pre-Commit Checklist: run unit tests, run
integration tests when the dependency chain is touched, verify linting, and
never commit if any of them fail.

`superpowers:verification-before-completion` covers the same ground and covers
it harder. Its description is *"Use when about to claim work is complete,
fixed, or passing, before committing or creating PRs"*. It carries an Iron Law,
a five-step gate function — identify the command, run it fully, read the
output, verify it confirms the claim, only then claim — plus a Red Flags list
naming the exact failure modes: *"About to commit/push/PR without
verification"*, *"Thinking 'just this once'"*, *"ANY wording implying success
without having run verification"*.

Our checklist says which commands to run. Theirs says what it means to have
actually run one.

**But delegation is not the obvious move here, and the reason matters.** That
skill triggers on a *state* — being about to claim success — with no phrase
trigger. `commit-helper` triggers on "let's commit", which a human types.
Across roughly fifty completion claims in the session that produced this item,
`verification-before-completion` fired zero times, while `commit-helper` fired
whenever asked. The weaker document is the one that actually runs.

So the fix is not to remove our checklist in favour of theirs. It is to have
the reliable trigger pull in the stronger discipline: keep the checklist,
and cite the gate function rather than paraphrasing what verification means.

**Scope Decisions**:
- **Cite, do not delete.** Deleting the checklist would trade something that
  fires for something better written that does not.
- **Do not restate the gate.** Naming it and pointing at it is the rule from
  [XAS-027k](xas-027k.md); copying its five steps would recreate the drift that
  item exists to prevent.
- **Nothing changes about integration tests or linting.** Those are specific to
  this marketplace's harness and superpowers says nothing about them.

**Acceptance Criteria**:
- [x] `commit-helper`'s Pre-Commit Checklist cites
      `superpowers:verification-before-completion` as the definition of having
      verified, rather than paraphrasing it.
- [x] The checklist keeps its concrete commands and its integration-test and
      linting rules.
- [x] The skill does not reproduce the gate function's steps.
- [x] `plugin.json` and `marketplace.json` bumped (patch — wording) and in
      agreement. **Satisfied differently:** this landed inside the unreleased
      `2.0.0` from [XAS-030](xas-030.md) rather than taking its own patch
      number, since no installer has seen `2.0.0` yet.
- [x] All existing tests continue to pass.

**Out of scope**:
- Removing the checklist.
- Any change to `superpowers`.
