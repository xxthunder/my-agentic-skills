# [XAS-033] ✅ DONE - Backlog TOC invariant tests

**Status**: Done (2026-08-24)
**Priority**: Medium
**Component**: `tests/dev/backlog/test_backlog_toc.py` (new)

**Related**: Mirrors [XAS-027h](xas-027h.md), which did the same for the ADR
log. Found while sweeping docs before merging XAS-027k.

**Summary**:
As a maintainer, I want the backlog's structural invariants checked by CI, so
that a table of contents disagreeing with its item files fails a build rather
than misleading the next reader.

**Description**:
`docs/backlog/README.md` is the **authoritative** record of item status — the
`backlog-ops` skill states that where a file and the README disagree, the README
wins. That makes disagreement worse than in the ADR log, where the files win and
the index is a regenerable cache: here a stale TOC is not a cache miss, it is the
wrong answer.

Nothing checks it. Two defects were found by hand while sweeping documentation
before merging XAS-027k, both introduced during this epic:

- **XAS-032** was `In Progress` in its file and listed under `### Open`. The
  commit that recorded its investigation ticked a criterion and set the status
  but never moved the TOC line.
- Earlier in the same epic, a TOC line was inserted out of ID order and another
  left a stray blank line inside the list.

Neither is detectable by `architecture-scan`, which compares the architecture
document against code structure and does not read the backlog at all.

**Scope Decisions**:
- **Tests run against this repository's own `docs/backlog/`**, not a fixture.
  A fixture would prove the fixture is well-formed. Negative cases are built in
  `tmp_path`, as [XAS-027h](xas-027h.md) does.
- **Structure only, never content.** Whether an item's acceptance criteria are
  any good is a refinement question and stays one.
- **The README wins, and the tests encode that.** A mismatch is reported as the
  file disagreeing with the README, not the reverse, matching `backlog-ops`.
- **Skip cleanly when `docs/backlog/` is absent**, so a fork without one sees
  skips rather than failures.
- **The epic cascade is checked only where it is mechanical.** An epic must not
  be `Done` while a letter-suffixed substory is not. Whether an epic *should*
  have moved to `In Progress` is a judgement `backlog-ops` makes with the user.

**Acceptance Criteria**:
- [x] Every item file appears in the TOC exactly once, and every TOC entry
      points at a file that exists.
- [x] Each item's `**Status**:` matches the TOC section it is listed under.
- [x] Each item's heading ID matches its filename.
- [x] Entries within a section are in ID order.
- [x] Done markers are **consistent**, not mandated. Eight items — XAS-016
      through XAS-024 — are Done with a bare status and no heading prefix. The
      backlog Notes document them as legacy bare-ID substories predating the
      convention, and inventing completion dates now would be fabrication. The
      check instead verifies that a date parses where one exists, and that a
      heading marked DONE has a Done status.
- [x] No epic is `Done` while any letter-suffixed substory is not.
- [x] Relative links inside item files resolve.
- [x] A malformed backlog built in `tmp_path` fails each check that should catch
      it; the negative cases are not assumed.
- [x] Tests pass on both ubuntu and windows in CI. **174 passed, 0 skipped** on both.
- [x] No plugin version bump — this touches only `tests/`.

**Out of scope**:
- Validating acceptance-criteria wording or item quality.
- Enforcing that an epic moves to `In Progress` when a substory does. That is a
  cascade judgement, not an invariant.
