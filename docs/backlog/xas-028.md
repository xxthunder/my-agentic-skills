# [XAS-028] Declare the `superpowers` dependency in the marketplace

**Status**: Open
**Priority**: High
**Component**: `plugins/xxthunder-dev-skills/.claude-plugin/plugin.json`,
`.claude-plugin/marketplace.json`, `README.md`, `CONTRIBUTING.md`,
`plugins/xxthunder-dev-skills/skills/refinement/SKILL.md`,
`plugins/xxthunder-dev-skills/skills/tdd-workflow/SKILL.md`

**Related**: [XAS-027](xas-027.md) surfaced the coupling — [XAS-027c](xas-027c.md)'s
hook payload exists specifically to contend with `superpowers:brainstorming`'s
spec-writing step, which is only coherent if `superpowers` is present. This item
is not part of that epic: it is marketplace metadata, independently useful, and
closer in kind to [XAS-004](xas-004.md)'s tooling family.

**Summary**:
As a user installing `xxthunder-dev-skills`, I want the plugin to declare that it
requires `superpowers`, so that the skills I install work as designed instead of
silently degrading against a peer plugin that happens not to be there.

**Description**:
These dev skills are authored and used alongside `superpowers`. The workflow they
assume is real — design is brainstormed through `superpowers:brainstorming` and
lands in a backlog item — but that assumption appears **nowhere** in the
repository. `superpowers` currently has zero occurrences across `plugins/`,
`README.md`, `CLAUDE.md` and `CONTRIBUTING.md`. Someone installing this plugin
alone gets skills built around a collaborator that is not there.

Claude Code's plugin manifest supports this directly via a `dependencies` array.
The field is real but almost unused in the wild — none of the 114 plugin
manifests cached locally declare one — so the mechanics below are worth writing
down rather than rediscovering.

`superpowers` lives in the `claude-plugins-official` marketplace, sourced from
`github.com/obra/superpowers.git`. Cross-marketplace dependencies are refused by
default; the allowlist lives in the **root** marketplace — the one hosting the
plugin being installed, which is this one — so permitting it is entirely a local
decision and does not chain trust through third parties.

Declaring the dependency is only half of making it explicit. The manifest makes
installation correct; prose makes the coupling legible. Both are in scope.

**Scope Decisions**:
- **Scoped to `xxthunder-dev-skills` only.** `xxthunder-paperless-skills` has no
  such dependency and must not inherit one.
- **Object form, but unversioned** —
  `{"name": "superpowers", "marketplace": "claude-plugins-official"}`. The
  `marketplace` key is required, not optional: a bare string resolves `name`
  *within the declaring plugin's own marketplace*, so `"superpowers"` alone
  would be looked up in `xxthunder-agentic-skills` and fail. `version` is
  omitted deliberately. Version constraints resolve
  against git tags named `superpowers--v{version}` on the dependency's own
  repository. That is a Claude Code convention that upstream does not follow, and
  a constraint with no satisfying tag fails the install outright with
  `no-matching-tag`. An unversioned entry skips tag resolution and tracks
  whatever the marketplace provides. Revisit only if upstream starts tagging to
  the convention.
- **The dependency is hard, and that is accepted knowingly.** Claude Code has no
  optional or peer dependency model. Consequences: installing this plugin
  auto-installs `superpowers`; enabling this plugin transitively enables it; and
  `claude plugin disable superpowers` **fails** while this plugin is enabled,
  reporting that it is still required. For a marketplace whose dev skills are
  built around that workflow this is honest rather than presumptuous, but it is
  imposed on every installer and should not be reversed casually.
- **Do not pin `allowCrossMarketplaceDependenciesOn` to more than is needed** —
  the allowlist names `claude-plugins-official` and nothing else.
- **Version-bump interaction with [XAS-027c](xas-027c.md).** This item changes
  `plugin.json` but nothing under `plugins/<plugin-name>/skills/`, so today's
  wording in `CLAUDE.md` and `CONTRIBUTING.md` does not strictly require a bump.
  It plainly warrants one. Bump regardless, and treat this as further evidence
  for the widening XAS-027c already carries.

**Acceptance Criteria**:
- [ ] `plugins/xxthunder-dev-skills/.claude-plugin/plugin.json` declares
      `"dependencies": [{"name": "superpowers", "marketplace": "claude-plugins-official"}]`,
      with no `version` key.
- [ ] `.claude-plugin/marketplace.json` declares
      `"allowCrossMarketplaceDependenciesOn": ["claude-plugins-official"]`.
- [ ] `xxthunder-paperless-skills` declares no dependency and is otherwise
      untouched.
- [ ] Both manifests remain valid JSON and the field placement matches the
      documented schema.
- [ ] Verified against a real install rather than by inspection: with the
      marketplace added, `claude plugin install xxthunder-dev-skills` resolves
      `superpowers`, and `claude plugin list --json` reports **no** `errors`
      field for `xxthunder-dev-skills`.
- [ ] Verified that `claude plugin disable superpowers` is refused while
      `xxthunder-dev-skills` is enabled, and that the error names this plugin.
      This is the user-visible cost of the hard dependency; confirm it behaves as
      documented rather than assuming.
- [ ] `README.md` gains a **Requirements** section stating that
      `xxthunder-dev-skills` requires `superpowers`, why, and that installing
      this plugin pulls it in automatically.
- [ ] `CONTRIBUTING.md`'s acceptance bar acknowledges that a dev skill may rely
      on `superpowers`, so a contributor does not treat such a reference as a
      portability violation under point 3.
- [ ] The skills that actually hand off name the handoff in their own text —
      at minimum `refinement` (design work goes to `superpowers:brainstorming`,
      and its output lands in the backlog item) and `tdd-workflow` (its
      relationship to `superpowers:test-driven-development`, which overlaps it).
- [ ] `plugin.json` and `marketplace.json` versions bumped (minor) and in
      agreement.
- [ ] All existing tests continue to pass.

**Out of scope**:
- Declaring dependencies for `xxthunder-paperless-skills`.
- Version-constraining `superpowers`. See the Scope Decision above.
- Resolving the overlap between this repo's `tdd-workflow` and
  `superpowers:test-driven-development`. Naming the relationship is in scope;
  deciding whether one should be retired is a separate conversation.
- Any change to `superpowers` itself.

**Open Questions**:
- **Does an unversioned cross-marketplace dependency survive
  `/reload-plugins` and background auto-update?** The documentation says a
  missing dependency is reinstalled provided its marketplace is already
  configured, and that dependencies from an unconfigured marketplace are left
  unresolved. A user who has not added `claude-plugins-official` is therefore the
  untested path. To be checked during the install verification above, not
  assumed.
