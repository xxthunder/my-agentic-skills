# [XAS-024] Persist scanner type (simplex/duplex) in `naps2-scan` config

**Status**: Done
**Priority**: Medium
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/naps2-scan/

**Summary**:
During UAT of XAS-021/XAS-023, the skill asked "simplex or duplex scanner?" on every double-sided document. Scanner type is a property of the hardware (or at most the profile), not of the individual document — asking per-document is friction without payoff.

**Description**:
Extend the config schema introduced in XAS-021 with `default_scanner_type` (`simplex` or `duplex`). The skill reads it like `default_ocr_lang`: apply as default when present, ask only if missing, persist on successful scan. Users who swap scanners can override once per session; the next successful scan overwrites the default.

**Scope Decisions**:
- **Flat field, not per-profile map.** The overwhelming majority of users have one scanner. A map keyed by profile name is YAGNI; revisit if real multi-scanner users surface.
- **Ask at most once per session**, only when the user answered "double-sided: yes" AND no value is stored in config AND no value was supplied this session.
- **No change to `read_config.py`** — it already emits whatever keys are in the JSON.
- **`write_config.py` gains a `--scanner-type` flag** that validates against `{simplex, duplex}`.

**Dependencies**:
- XAS-021 (config persistence scaffolding)

**Acceptance Criteria**:
- [x] `write_config.py` accepts `--scanner-type` with values `simplex` or `duplex`
- [x] `SKILL.md` Config section schema includes `default_scanner_type`
- [x] `SKILL.md` Step 1 uses stored `default_scanner_type` instead of asking per-document
- [x] `SKILL.md` Step 7 (persist config) passes `--scanner-type` alongside the other flags

- [x] Plugin version bumped (will be reset during pre-merge rebase per XAS-015 release plan)
