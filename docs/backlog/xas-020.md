# [XAS-020] Document `ExcludeBlankPages` profile option in `naps2-scan`

**Status**: Done
**Priority**: Low
**Epic**: XAS-015
**Component**: plugins/xxthunder-paperless-skills/skills/naps2-scan/

**Summary**:
As a user scanning documents that include trailing blank pages (e.g., simplex scans where the back of the last page is blank), I want the skill to document how to avoid manual page deletion so that my scans come out clean without post-processing.

**Description**:
UAT of `naps2-scan` (XAS-018) produced a 3-page PDF with a blank trailing page, which the user had to delete manually. NAPS2 profiles expose an `ExcludeBlankPages` setting that drops blank pages server-side during the scan, but `NAPS2.Console.exe` does not expose it as a CLI flag — it must be configured in the profile.

**Scope Decisions**:
- **Path (a), zero code**: document the profile option in `SKILL.md` (prerequisites + troubleshooting). Do NOT add a post-scan blank-page strip in the skill itself.
- Rationale: keeps the skill thin and pushes configuration to where it already lives (the NAPS2 profile). A post-scan strip would duplicate functionality NAPS2 already provides and add rasterization dependencies.

**Acceptance Criteria**:
- [x] `SKILL.md` prerequisites mention enabling `Exclude Blank Pages` in the NAPS2 profile for documents with mixed-content stacks
- [x] Troubleshooting section covers "trailing blank pages in output" → point at the profile setting
- [x] Version bumped in `plugin.json` and `marketplace.json`
